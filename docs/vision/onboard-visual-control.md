# 树莓派本地轨道视觉闭环

## 目标与边界

活动任务入口不再执行按固定时间直线前飞。每个运动脉冲必须依次经过：

    树莓派 CSI 相机
      -> 树莓派本地 YOLO 分割
      -> 掩膜逐行轨道几何
      -> 三帧中值融合
      -> 有界的机体系速度/偏航速度
      -> MAVSDK -> PX4

图像和掩膜不发送到地面计算机。地面计算机只负责 QGroundControl 监视与人工
接管。Gazebo 测试中的 /tmp/uav_demo_camera 只是树莓派相机的仿真替身，推理
与控制仍在运行 uav_demo.onboard_cli 的同一个本地进程内完成。

## 不使用 YOLO 外接框

蓝色矩形框只用于审阅显示，不能计算控制量。当前算法使用分割掩膜：

1. 只取图像高度 50% 到 88% 的近中场，避开 Spring 模型在画面顶部产生的
   伪掩膜；
2. 在 28 条扫描行上找出掩膜连续段；
3. 用所有有效段的最左、最右像素形成当前行的轨道包络；
4. 由包络中点得到当前行轨道中心；
5. 按透视规律检查轨道宽度：越靠远处应越窄，突然变宽的扫描行被视为边缘
   伪分割；
6. 对中心点进行两轮残差剔除和直线拟合。

近场归一化横向误差为：

    e_lateral = (x_near - 0.5) / 0.5

正值表示轨道中心位于画面右侧。航向误差由近、远中心点的像素方向计算，正值
表示前方轨道朝画面右侧延伸。

该规则适用于当前直轨 Demo。道岔附近宽度不再单调，必须先由道岔识别选择分支，
再分别拟合候选轨道；不能直接沿用本规则跨越道岔。

## 当前控制映射

默认每次使用 3 帧，至少 2 帧通过模型和几何检查才接受，并对置信度、横向误差
和航向误差取中值。接受后产生一个 0.75 s 的机体系速度脉冲：

- 最大前进速度：0.12 m/s；
- 最大横向速度：0.10 m/s；
- 最大偏航速度：8 deg/s；
- 横向误差达到 0.50 或航向误差达到 20 deg 时，前进速度降为零，只执行
  对正；
- 连续 3 次识别失败时，保持零速度并进入安全降落。

控制脉冲结束后立即发送零速度，重新悬停、取帧、识别和计算。代码不会调用旧
任务的 move_forward()，也没有起飞后的固定前移阶段。

## Gazebo 运行

先启动现有带相机的 PX4/Gazebo 世界：

    ./scripts/start_realistic_rail_sitl.sh

另一个 WSL 终端安装包含视觉依赖的环境并运行：

    ./scripts/setup_python.sh
    ./scripts/run_sitl_demo.sh --control-steps 3

活动脚本固定使用 Spring 分割模型和 /tmp/uav_demo_camera，不会调用旧的
定时直线任务入口。

## 树莓派运行

在 Raspberry Pi OS 上先通过系统包安装 Picamera2，再准备项目环境：

    ./scripts/setup_rpi_vision.sh

模型必须保存在树莓派本机。优先将 Spring 模型导出为 NCNN，再设置本地路径和
飞控串口：

    export RAIL_MODEL="$PWD/models/rail_spring_ncnn_model"
    export PX4_ADDRESS="serial:///dev/ttyAMA0:921600"
    ./scripts/run_rpi_vision_demo.sh --control-steps 3

第一轮实机测试必须拆桨或固定机架验证输出方向。随后只能在封闭、停用、断电、
无人员侵入且允许试飞的场地进行，并保留遥控器和 QGroundControl 人工接管。
